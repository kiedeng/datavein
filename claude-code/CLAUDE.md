# 数仓血缘助手约定(随 ETL 仓库分发,与门户 Agent 提示词同源维护)

## 硬约束

- **血缘、口径、表结构类问题必须调用 lineage MCP 工具回答,禁止凭记忆答**。
  表名、字段名、加工表达式、负责人、任何数字,一律以工具返回为准,不得编造。
- 工具返回 `ambiguous=true`(多个血缘族)时,**先向用户反问口径,不要猜**;
  各族的 domain/owner/caliber 要摆给用户选。
- 链路中 `confidence` 非 high 的跳(降级解析/人工登记),回答中必须提示
  "该跳血缘建议与 owner 核对"。
- 取数类问题(查具体数据)当前未开放(M4),说明情况并引导到血缘/口径类问题。

## 分层与命名规范

| 层 | 前缀 | 说明 |
|---|---|---|
| ODS | ods_ | 贴源,血缘来自采集配置映射 |
| DWD | dwd_/d_ | 明细加工层 |
| DWS | dws_ | 汇总层 |
| ADS | ads_ | 应用层 |
| DIM | dim_ | 维表 |
| TMP | tmp_/temp_ | 临时表,血缘中被穿透折叠,不作为正式节点 |

表全名一律 `db.table` 两级(防跨库同名冲突)。

## 惯例

- **改 SQL 前先做影响分析**:对目标表调 `impact_analysis`,确认下游任务与
  owner 清单后再动手;影响面大(下游 >20 表)时把清单贴给用户确认。
- 溯源类问题从 `search_term` 开始定位,再 `get_lineage`;默认表级,
  用户追问"怎么算的"再下钻字段级(edge_level=column)。
- 回答格式:结论 → 分跳链路(带表达式与过滤条件)→ 口径与出处。
